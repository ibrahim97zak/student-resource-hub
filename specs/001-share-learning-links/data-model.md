# Data Model: Student Resource Hub

## Entity and relationships

One application table, public.resources. owner_id references auth.users(id), with deletion
restricted while resources exist (account deletion is outside this version). No profile,
topic, vote, or comment table. No URL uniqueness constraint.

| Column | Type/default | Rules |
| --- | --- | --- |
| id | uuid, gen_random_uuid(), primary key | Generated by database; clients cannot insert/update it |
| owner_id | uuid, not null, foreign key | Insert equals authenticated user; immutable afterward |
| title | text, not null | Trim before storage; code-point length 1..100 |
| url | text, not null | Trim; absolute HTTP/HTTPS URL with valid host and full syntax |
| topic | text, not null | Exactly React, JavaScript, or AI |
| description | text, nullable | Null or 0..300 code points; preserve supplied whitespace |
| created_at | timestamptz, not null, now() | Database default; clients cannot insert/update it |

Empty description may be stored as null; nonempty description must round-trip unchanged.
List order: created_at DESC, id DESC. An index on that pair is sufficient; no search index
is needed for the small fetched collection. A foreign-key/owner index may be added for
ownership checks; no premature full-text indexing.

## Validation boundary

Use NOT NULL plus CHECK constraints for title, topic, length, scheme and full URL validity;
CHECK alone does not reject null, so required columns also need NOT NULL. A focused
normalization trigger trims title/url using the same explicit whitespace set as the form.
Use character length, not byte length or UTF-16 code-unit length.

The accepted URL contract is an absolute URL under the WHATWG HTTP(S) parsing model with
nonempty hostname, after surrounding whitespace trim. The form must reject missing explicit
http:// or https:// authority notation before URL parsing, rather than accept parser-repaired
relative-looking inputs. Both layers must reject missing host, invalid host/brackets/port,
embedded raw whitespace/control characters and invalid URL syntax. No destination fetch.
Database syntax validation uses a pure immutable SQL/PLpgSQL helper invoked by a constraint;
its internal parsing is implementation work, not included in this planning artifact.

Acceptance corpus must include ordinary hostnames, subdomains, localhost, numeric addresses,
IPv6 bracket notation, international domains, query/fragment, optional credentials/ports,
uppercase schemes, and escaped path characters. Cover absent scheme/host, malformed
brackets/ports, unsupported scheme, embedded controls and spaces. Compare form and direct
write results, including Unicode/trimming boundaries; any parser discrepancy requires
correction before completion, not a silent reduction to a scheme-prefix check.

Explicit planning answer: full database URL validation is retained. No new server or
unverified extension is part of this design. Full parser compliance is a meaningful schema
verification obligation; if it cannot be delivered within the assigned task, report the
blocker instead of claiming FR-020 complete.

## Grants and policies

Revoke existing broad privileges from anon and authenticated before granting precisely
what is needed. Authenticated gets SELECT, DELETE, INSERT on owner_id/title/url/topic/
description only, and UPDATE on title/url/topic/description only. Grant required schema
usage, but no TRUNCATE, REFERENCES, TRIGGER or client access to Auth tables. Keep helper
functions least-privileged; no SECURITY DEFINER write path or RLS bypass is needed.

Enable RLS before exposing the table. All policies target authenticated only:

| Operation | USING (existing row) | WITH CHECK (new/resulting row) |
| --- | --- | --- |
| SELECT | true | Not applicable |
| INSERT | Not applicable | auth.uid() = owner_id |
| UPDATE | auth.uid() = owner_id | auth.uid() = owner_id |
| DELETE | auth.uid() = owner_id | Not applicable |

Thus everyone signed in reads, but only owners mutate. Changing owner to someone else
fails the resulting-row check; column privileges prohibit supplying owner_id on update
altogether. Database-generated fields also remain immutable through column privileges.
Anonymous requests receive no rows/access; the browser also gates the collection screen.

## Lifecycle and migrations

Create -> persisted owned resource -> edit the four content fields -> confirmed deletion.
Cancellation changes nothing. Edits retain id/owner_id/created_at; deletion has no soft-delete
state. Failed writes leave existing data unchanged. Distinct records may share any URL.

Later implementation writes versioned SQL under supabase/migrations, applying table,
normalization/validation, grants and policies atomically where practical. The instructor
manually reviews and runs each pending migration in the correct Supabase project's SQL
Editor during the session, then records filename, project identifier, application time,
and observed checks without credentials. Do not alter Auth user records to test ownership.

A merged migration file is not proof of remote application. Inspect remote columns,
constraints, grants, RLS enabled status, and policies, then run authenticated-user tests.
Do not rerun non-idempotent migration SQL blindly or automatically drop production tables;
fix failures with an explicitly reviewed forward migration. No SQL is created/applied now.
